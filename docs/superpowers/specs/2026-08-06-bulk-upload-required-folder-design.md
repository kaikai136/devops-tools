# 批量上传必填提示与文件夹上传设计

## 背景

批量执行页的上传视图当前只支持选择多个文件，任务名称、目标机器、远程目录、上传文件等必填项主要依赖按钮禁用。用户点击“检查文件”“开始上传”或执行脚本时，如果缺少必填项，界面没有明确告诉用户缺少什么。选择文件夹上传时，需要保留本地目录层级。

## 目标

- 必填字段标题后显示红色 `*`。
- 点击执行、检查文件、开始上传时，按当前视图提示缺失的必填项。
- 批量上传支持选择文件夹，并保留本地相对目录结构。
- 后端保存、检查和上传文件时使用安全的相对路径，拒绝绝对路径和 `..` 路径穿越。
- 上传嵌套文件前自动创建远程父目录。

## 非目标

- 不重做批量执行页整体布局。
- 不改变主机选择器的选择流程。
- 不新增压缩包上传或服务器端解压功能。
- 不改变已有单文件、多文件上传的默认行为。

## 前端设计

上传视图保留现有文件选择入口，并新增“选择文件夹”入口。文件选择输入继续使用 `multiple`；文件夹选择输入使用浏览器支持的目录选择属性。前端对每个文件提取显示路径：优先使用 `webkitRelativePath`，为空时使用 `name`。文件列表展示该路径，让用户能看到目录层级会被保留。

提交 `FormData` 时，除 `files` 外同步提交 `relativePaths`，顺序与 `files` 完全一致。上传检查接口也使用这些相对路径作为 `filenames`，因此重复文件检查会检查远程完整路径，例如 `/tmp/release/config/app.yml`。

必填提示采用统一前端校验函数：

- 执行视图校验：任务名称、目标机器、脚本内容。
- 上传视图校验：任务名称、目标机器、文件或文件夹、远程目录。
- 点击操作按钮时，如果缺项，使用现有 `showToast` 提示第一个缺失项。
- 按钮仍可点击触发校验，只有权限不足、正在执行/上传/检查、或覆盖警告未确认等状态继续禁用。

## 后端设计

后端接收 `relativePaths`，将其与上传文件按顺序配对。路径规范化规则：

- 使用 POSIX 风格 `/` 作为内部分隔符。
- 去掉空片段和 `.`。
- 拒绝空路径、绝对路径、Windows 盘符路径、包含 `..` 的路径。
- 每个片段仍复用文件名安全规则，避免特殊字符或空名称。

`BulkExecutionUploadFile.filename` 保存安全相对路径；`remote_path` 使用 `join_remote_path(remote_directory, relative_path)`，因此保留目录层级。重复文件判断继续基于 `remote_path`。

运行上传时，如果远程路径包含父目录，先对目标主机执行一次安全的 `mkdir -p <parent>`，然后再执行现有 copy 模块。父目录创建失败时，该文件传输失败并记录错误，不继续对该文件执行 copy。

## 错误处理

- 前端缺失必填项：明确提示“请填写任务名称”“请选择目标机器”“请选择上传文件或文件夹”“请填写远程目录”等。
- 后端路径非法：返回 400，提示上传路径不合法。
- 文件数量和相对路径数量不一致：返回 400，提示上传文件信息不完整。
- 远程目录创建失败：该主机对应传输项失败，错误显示在任务详情中。
