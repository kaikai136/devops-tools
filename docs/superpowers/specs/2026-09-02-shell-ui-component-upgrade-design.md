# 主框架 UI 组件升级设计

## 目标

把登录后的主框架和导航层升级成更统一的组件化体验，使用 `Element Plus` 承载结构型控件，使用 `Ant Design Vue FloatButton` 承载全局快捷操作。

目标不是重做业务功能，而是让侧边栏、顶栏、面包屑、用户菜单和快捷入口更整齐，降低当前手写布局带来的割裂感。

## 范围

- `App.vue` 的主壳层
- 左侧导航
- 顶栏操作区
- 用户菜单
- 全局快捷按钮
- 相关基础样式和依赖声明

## 方案

采用“保留现有路由与业务页，重做壳层交互”的中等改造方案。

### 组件映射

- 侧边栏：`el-menu` / `el-sub-menu` / `el-menu-item`
- 顶栏动作：`el-button` / `el-tooltip`
- 用户菜单：`el-dropdown`
- 面包屑：`el-breadcrumb`
- 抽屉式补充动作：`el-drawer`
- 全局快捷入口：`FloatButton.Group`

### 页面结构

- 左侧导航保留分组，但交互改成组件库标准行为
- 顶栏保留当前信息密度，但统一按钮尺寸、间距和 hover 状态
- 右下角新增浮动快捷组，放置主题切换、刷新仪表盘、回到顶部等高频动作
- 业务页面继续沿用现有 Vue 组件，不做大规模重写

## 取舍

### 方案 A: 轻量接入

只把按钮、下拉菜单、提示层替换成组件库，布局基本不变。

- 优点：改动最小，最快落地
- 缺点：整体观感提升有限，还是会保留较多手写壳层痕迹

### 方案 B: 壳层重构

重做主框架导航与顶栏，业务页保持原样。

- 优点：统一感明显，风险可控，适合当前仓库
- 缺点：需要补一轮样式适配和测试

### 方案 C: 全面迁移

把很多业务页也一起迁到组件库风格。

- 优点：一致性最好
- 缺点：工作量大，回归面太广

## 决策

采用 **方案 B**。

原因是当前项目已经有较成熟的业务页和权限流，最值得先统一的是壳层，而不是把所有工具页一次性翻新。

## 非目标

- 不改后端接口
- 不改路由结构
- 不改权限模型
- 不重写各业务页内部表单和表格
- 不引入新的业务流程

## 验收标准

- 登录后主框架使用组件库完成主要导航与交互
- 侧边栏折叠、展开、分组切换行为保持可用
- 顶栏中的常用操作改成统一的组件库样式
- 右下角出现浮动快捷按钮组
- 深色模式和移动端布局仍然可用
- 现有页面功能不回退

## 校验

- 安装并接入 `Element Plus` 和 `Ant Design Vue`
- 运行前端构建
- 运行与主框架、导航相关的测试
- 检查桌面端和移动端布局
